# 校园顺路 CampusDash 前端

React 18 + TypeScript + Vite，按发布用户、跑腿员和平台管理员划分三个工作区。

```bash
npm install
npm run dev
npm run build
```

本地访问 http://localhost:5273；`/api` 代理到后端 8080。

| 工作区 | 演示账户 | 页面 |
| --- | --- | --- |
| 用户端 | 1001 | 服务首页、发布订单、我的订单、限时活动、我的钱包、消息中心 |
| 跑腿端 | 2001、2002 | 接单大厅、我的接单、收入钱包、服务信用、消息中心 |
| 平台端 | 9001 | 争议处理、订单查询 |

退出当前账户后，选择另一个入口登录。登录角色由后端返回，刷新时通过 `/api/auth/me` 校准，验证成功后才展示工作区。不同工作区使用独立导航与路由，旧 `/square`、`/mine` 等链接会映射到当前身份允许的页面。

用户订单只查询 `PUBLISHED_BY_ME`，跑腿履约列表只查询 `GRABBED_BY_ME`。跑腿大厅按服务类型、关键词和悬赏排序；订单列表按状态筛选。接单大厅的分类、关键词和悬赏排序由服务端在分页之前执行，覆盖整个校区的待接单订单。个人订单分类数量统计当前加载的数据，可加载更多。分页请求串行执行，刷新或操作后保留已加载页，切换查询时丢弃旧响应。

订单状态与 `availableActions` 仍由后端计算；前端再按工作区能力收窄操作展示。取消、确认结算和发起争议带页面内确认；仲裁需选方向后再次确认。活动请求发送前保存原请求号及内容，结果未确定时禁止新建请求，可继续查询或使用原请求重试。后端同时拦截跨角色 API 请求并检查订单归属。

WebSocket 实时更新，连接不可用时以轮询补充。WebSocket 经同源 `/ws` 代理连接。退出会清理旧连接并撤销服务端 access token；旧请求返回的过期响应不会注销新会话。同源其他标签页切换或退出账户时，当前页重新加载以同步身份。

这是演示账户模型：默认发布用户由 `dash.auth.publisher-ids` 配置（1001），管理员由 `dash.auth.arbitrator-id` 配置（9001），其余演示与压测身份为跑腿员。尚未包含正式账号注册、身份认证、跑腿入驻审核、充值或提现流程。

整体整改方案、权限矩阵和验收记录见 [系统角色与体验整改方案](../docs/系统角色与体验整改方案.md)。
